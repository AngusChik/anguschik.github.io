Problem

Phone-based bookings make it hard to track barber availability, prevent double-booking, and give clients a clear view of what services are on offer and when they can be seen.

Process

  • Modelled Barbers, Services, and Appointments with slug-based routing per barber
  • Built booking conflict detection to prevent overlapping appointments
  • Linked Booksy URL support for barbers already using external booking tools

Learnings

Availability logic is where booking systems get complicated fast. Handling time zones, service durations, and slot conflicts correctly required careful model-level logic before the UI could be trusted to reflect real availability.

04 Full-Stack 2025

A Django appointment booking system for a barbershop — managing barbers, services, and scheduling in one clean backend.

The system supports multiple barbers with individual slugs, service listings with duration and pricing, and appointment booking with conflict validation. Each barber can optionally link to an external Booksy profile for clients who prefer that flow.

Outcome

A reliable booking backend that replaces phone scheduling with structured appointment management.
